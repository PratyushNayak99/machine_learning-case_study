# ForgeWatch AI: Target Definitions & Semantic Specifications

A core academic requirement of ForgeWatch AI is establishing precise, defensible mathematical and domain definitions for all target variables across the four studies. Failure concepts must never be conflated.

---

## 1. Taxonomic Matrix

| Student | Dataset | Target Identifier | Problem Type | Mathematical Domain | Real-World Operational Interpretation |
|---|---|---|---|---|---|
| **Student 1** | AI4I 2020 | `Machine failure` | Binary Classification | $y \in \{0, 1\}$ | **Simulated Failure Incident:** $1$ indicates a physical machine failure state generated by the simulation model; $0$ denotes nominal simulated operation. |
| **Student 2** | Scania Trucks | `class` | Binary Classification | $y \in \{0, 1\}$ (`neg` $\to 0$, `pos` $\to 1$) | **APS Component Localization:** $1$ indicates failure specifically in the Air Pressure System; $0$ indicates a failure in a NON-APS system (truck is NOT healthy). |
| **Student 3** | Hydraulic Systems | `cooler_condition` | Multi-Class Classification | $y \in \{3, 20, 100\}$ | **Component Degradation Grade:** $3$ indicates near total failure (efficiency $\approx 0\%$); $20$ indicates reduced cooling efficiency; $100$ indicates pristine/full efficiency. |
| **Student 4** | MetroPT-3 | `event_failure` | Supervised Window Detection | $y \in \{0, 1\}$ (Uncertain $\to \text{excluded}$) | **Air Compressor Failure Event:** $1$ denotes a sensor time window overlapping a confirmed maintenance failure event; $0$ denotes nominal operation outside a 6-hour exclusion buffer. |

## 2. Detailed Study Targets

### Student 1: AI4I 2020 Predictive Maintenance
- **Target Variable:** `Machine failure` (0 = No failure, 1 = Failure)
- **Positive Prevalence:** Approximately 3.39% (severe class imbalance, 339 failure cases out of 10,000).
- **Leakage Prevention Rule:**
  The dataset includes 5 individual failure mode columns:
  - `TWF` (Tool Wear Failure)
  - `HDF` (Heat Dissipation Failure)
  - `PWF` (Power Failure)
  - `OSF` (Overstrain Failure)
  - `RNF` (Random Failure)
  
  **Rule:** These columns are consequences/diagnostics of the machine failure event itself. Utilizing any of these columns as predictors for `Machine failure` constitutes catastrophic data leakage ($100\%$ target collinearity). They are strictly dropped during preprocessing.

---

### Student 2: APS Failure at Scania Trucks
- **Target Variable:** `class` (encoded: `neg` $\to 0$, `pos` $\to 1$)
- **Positive Prevalence:** ~1.67% in training set (1,000 positive cases out of 60,000).
- **Semantic Nuance:**
  - `pos`: Fleet vehicle brought into workshop with verified failure in the Air Pressure System (valves, compressors, drying cartridge).
  - `neg`: Fleet vehicle brought into workshop with verified failure in an *unrelated* subsystem (e.g., electrical, suspension, engine cooling).
  - **Critical Domain Caveat:** A `neg` prediction NEVER indicates that the truck is operating normally or is defect-free. It only indicates that APS components do not require servicing.
- **Asymmetric Maintenance Cost Function:**
  $$\text{Cost} = 10 \times \text{FP} + 500 \times \text{FN}$$
  - **False Positive (Cost = 10):** Unnecessary inspection of APS components by a workshop mechanic.
  - **False Negative (Cost = 500):** Missing an APS failure, resulting in an catastrophic on-road breakdown of the commercial vehicle, requiring heavy towing and urgent roadside repair.

### Student 3: Condition Monitoring of Hydraulic Systems
- **Target Variable:** `cooler_condition` (extracted from `profile.txt`, column 0)
- **Class Labels & Frequencies:**
  - `3`: Close to total failure (cooling efficiency near 0%) — ~732 cycles (~33.2%)
  - `20`: Reduced efficiency — ~732 cycles (~33.2%)
  - `100`: Full efficiency — ~741 cycles (~33.6%)
- **Type:** Balanced 3-class classification problem.
- **Leakage Prevention Rule:**
  `profile.txt` additionally contains other simultaneous component annotations:
  - Column 1: Valve condition (100, 90, 80, 73)
  - Column 2: Internal pump leakage (0, 1, 2)
  - Column 3: Hydraulic accumulator (130, 115, 100, 90)
  - Column 4: Stable flag (0, 1)
  
  These columns are component labels and must never be used as predictive inputs for `cooler_condition`.

---

### Student 4: MetroPT-3 Time-Series Windows
- **Target Variable:** `event_failure` (Window-level binary label)
- **Protocol:**
  - Failure event logs report compressor breakdowns (e.g., major air leakages causing pressure drop).
  - Positive Window ($y=1$): Sensor window falls inside an official maintenance failure event interval.
  - Buffer Window (Dropped): Sensor windows occurring within 6 hours before and after a failure event to eliminate transition ambiguity.
  - Negative Window ($y=0$): Sensor windows falling strictly in nominal operating regimes outside the buffer.
